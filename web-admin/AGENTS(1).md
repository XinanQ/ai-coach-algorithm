# AGENTS.md

## 背景与协作约束

这是一个多人协作的 GitHub 项目，我和同事并行开发、各自提交分支后再 merge。你(AI)做的任何代码改动都必须以「最大兼容性、最小 merge 冲突」为首要目标。请严格遵守以下规则。

## 规则

1. **最小改动原则**：只修改完成当前任务必需的代码，不顺手重构、不重排已有代码、不改动与任务无关的文件、import 顺序或格式化。保持现有代码风格、命名、缩进、引号习惯与原文件一致。

2. **保持接口向后兼容**：不要随意更改已有函数/组件的签名、参数、导出名、返回结构或公共 API。如确需扩展，优先用新增可选参数、新增函数/重载的方式，而不是修改现有的。删除或重命名任何公共符号前必须先说明影响范围。

3. **新增优于修改**：能通过新增文件/模块/函数实现的功能，就不要去改动公共文件。尽量把改动集中在少数文件、少数行，避免大面积 diff。

4. **不碰公共/共享区域**：除非任务明确要求，否则不要改动全局配置、共享工具函数、`package.json` 依赖版本、lockfile、构建配置、CI、`.gitignore` 等容易引发冲突的文件。若必须改，请单独说明原因。

5. **可定位、可回滚**：每个改动应逻辑独立、聚焦单一目的，方便 code review 和后续 cherry-pick。不要把多个无关改动混在一起。

6. **冲突友好的写法**：在列表、枚举、路由表、配置数组等多人易同时编辑的结构中，新增项尽量追加到末尾，避免插在中间或重排顺序。

7. **改动前先说明**：在动手前，先简要列出你打算改哪些文件、为什么这样改、是否影响公共接口，确认无误后再写代码。

## 完成后总结

请在完成后说明：改了哪些文件、是否新增/修改了公共接口、有没有潜在的 merge 风险点。
